Read this if you work here

This is not a manual for programmers. It follows one guest through one day and shows what the resort's system does at each step, and — just as important — what it refuses to do.

Every screenshot was taken from the system while it was running. Nothing was mocked up, staged, or drawn to look good. Where a screen did not work, this document shows that too, because a picture book of only the working parts is a brochure, not a record.

The one idea worth understanding first

The system never stores what you have. It stores everything that happened, and works out what you have by adding it up.

A cash box does not remember its balance — you count it. This system is the same. Stock is not a number someone types in; it is every delivery in and every sale out, summed. A guest's bill is not a total that gets edited; it is every charge minus every payment.

That sounds like a technical detail. It is the whole reason the numbers can be trusted: there is no field anyone can overwrite. To change what the stock says, you must add a movement — and a movement has a name and a time on it.
